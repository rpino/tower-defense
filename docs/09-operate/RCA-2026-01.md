# RCA-2026-01 — First Vercel deploy went to production without game art

| Field | Value |
|---|---|
| Severity | Sev-3: public URL broken for about 2 minutes, before it had been shared with anyone |
| Status | Resolved |
| Date | 2026-10-04 (times are PDT, UTC−7, from `vercel ls` deployment ages) |
| Author | Claude (blameless write-up). Reviewed by Pino |

## 1. Summary
The first `vercel deploy` for the new `tower-defense` project was meant to be a private **preview**, but Vercel published it to **production** because a project's first deployment always goes there. The deploy also left out the game's art: `.vercelignore` had an unanchored `assets/` pattern, which excluded `public/assets/` along with the raw art pack at the project root. Visitors to the production URL would have seen "Couldn't load the game — please refresh". A fixed preview was verified and promoted about 2 minutes later.

## 2. Impact
- **Who:** anyone opening https://tower-defense-weld.vercel.app between about 23:02 and 23:04 PDT. The link hadn't been shared with the jam or anyone else yet, so the likely real impact is **zero users**.
- **Data:** none. Static site, no data stored, nothing private exposed: docs, SDLC state, `.env.local` and the raw art pack all returned 404.
- **Process:** production went live before the explicit production go/no-go. Pino had approved a preview only.

## 4. Root cause (5 whys)
1. **Why did the site 404 on its art?** The upload didn't contain `public/assets/`.
2. **Why not?** `.vercelignore` listed `assets/`. Ignore files follow `.gitignore` rules, where a pattern without a leading `/` matches at **any** depth.
3. **Why was it written that way?** The intent was "skip the raw Kenney pack in `/assets`". The pattern was written from intent, not checked against the paths that actually exist (`assets/` and `public/assets/`).
4. **Why didn't a test catch it?** The release prep added a test for `vercel.json` but none for `.vercelignore`. The local `npm run build` doesn't use `.vercelignore`, so local checks passed.
5. **Why did it reach production instead of a preview?** Vercel sends a project's first deployment to production. This wasn't checked before deploying, so the release plan assumed the first deploy would be a preview.

**Root causes (system, not person):**
- (a) Platform-specific ignore semantics weren't verified, and the ignore file had no test.
- (b) The release plan assumed preview-first without checking the platform's first-deploy behaviour.

## 5. Why it wasn't caught earlier
- **Design §7 (rollout)** said "Vercel auto-detects Vite; no config needed". Config was added at release without a matching rollout check.
- **Release plan** had a smoke test after each deploy, which is what caught it quickly. But it had no pre-deploy check of what gets uploaded (e.g. `vercel build` locally, or listing the files to be uploaded).
- QA and Review tested the local `dist/`, which isn't affected by `.vercelignore`.

## 6. Fix
- **Immediate:** fixed preview verified, then promoted to production (Pino's go).
- **Permanent:**
  - Ignore patterns anchored to the root.
  - `tests/vercelignore.test.ts` fails if `public/` or `public/assets/` could be excluded, or if `.env*` isn't excluded.
  - `.env*` added to `.vercelignore`.
